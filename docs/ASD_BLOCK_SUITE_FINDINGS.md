# 48题长块实验：预检收益未扩展，当前保留16块

本轮已完成六类各8题、13组、3120次计时及144次额外机制回放。数据仍是同一开发集，验证48题和保留96题没有生成模型答案。结论是：**当前b16权重直接外推24/32块，没有形成可升级的性能增量；保留16块，停止这条实现的继续扫参，进入执行开销诊断。** 专用长块训练、其他模型或精度配置尚未由本轮评估。

固定Qwen3-8B/DFlash、FP32/eager、greedy、batch1、原Target输入和四策略。每个真实块长都实际前向；自然4096上限三重复，遵守EOS前128两重复；同题同卡随机交错。完整表、全部比较及质量在[结果表](ASD_BLOCK_SUITE_RESULTS.md)、`results/asd-block-suite/analysis.json`及`per-case.json`，运行前约定见[冻结协议](ASD_BLOCK_SUITE_PROTOCOL.md)。

## Utility24相对强参照

以下比较Utility24与基础ASD16，按题先取重复中位数，再算配对几何平均。正数表示更慢。区间是题级5000次bootstrap的时延比区间，1表示持平；有些区间包含1，不能把所有差异都说成已统计确认。

|类别|自然时延变化|自然比95%区间|等128时延变化/有效题数|ASD16→Utility24主正确|
|---|---:|---|---|---|
|GSM8K|+4.07%|[0.9769,1.1100]|+4.14% / 7|8/8→8/8|
|MATH-500|+8.68%|[0.9521,1.2336]|+15.89% / 8|7/8→7/8|
|MBPP|+16.41%|[1.0301,1.3078]|无共同128样本|6/8→6/8|
|HumanEval|+2.86%|[0.9444,1.1201]|无共同128样本|7/8→7/8|
|SQuAD|+4.18%|[1.0113,1.1022]|无共同128样本|6/8→6/8|
|合成JSON|+8.29%|[1.0448,1.1254]|+13.29% / 6|8/8→8/8|

Utility32相对ASD16的自然时延六类也均更慢，点估计约+4.48%至+15.13%。严格D24相对D16六类均更慢，约+3.91%至+20.46%；D32也均更慢。原D16相对同轮AR仍约1.35×至6.99×加速，原基线没有失效。

本批Utility24的最终正确数与ASD16相同。八题/类不能证明质量非劣；代码采用提供测试，HumanEval是完整函数指令版本，JSON为合成控制，不作为生产或官方pass@k成绩。

## 为什么六题预检看起来更好

1. **局部正例保留，但未迁移到更多开发题。** GSM885在本轮Utility24/Utility16等128仍快13.68%，相对ASD16也快10.54%。然而GSM8题整体相对ASD16慢4.14%；去掉这道预检重叠题，另外7道开发题的自然时延慢6.33%。
2. **参照强度很重要。** MATH329中Utility24/Utility16等128快23.31%，相对基础ASD16却慢10.88%，自然时延也慢9.36%。原ASD16本来就在这题表现较好。只看同一Utility自己的16块会高估新组合的价值，因此本轮预先冻结了跨块强参照。
3. **没有靠重复扩大题数。** 预检只有每类第一题，本轮每类8题；全部42道非预检重叠题依旧属于开发数据。它们在六类的Utility24/ASD16自然时延点估计也均更慢，约+2.72%至+21.27%。这些不是正式独立验证。

本轮保留了预检中的正例，也保留完整比较，没有把“所有题都变慢”当结论。主表时延比、总秒数和TPS使用不同汇总口径，不能互换。

## 性能变化来自哪里

冻结分解是：时延比＝输出长度比×Target调用密度比×每调用摊销成本比。下表仍为Utility24/ASD16；这是代数分解，每调用成本包括prefill、Draft和全部在线开销，不能解释成纯Target内核或独立因果贡献。

|类别|输出长度变化|每token调用密度变化|每调用摊销成本变化|
|---|---:|---:|---:|
|GSM8K|+0.31%|-0.97%|+4.77%|
|MATH-500|+0.27%|+2.75%|+5.48%|
|MBPP|-0.47%|+14.68%|+1.99%|
|HumanEval|-0.90%|-0.46%|+4.27%|
|SQuAD|0|+5.20%|-0.97%|
|合成JSON|0|+4.01%|+4.12%|

主要问题是长块未持续减少有效调用，部分场景调用密度还上升。较小的调用密度收益也会被每次调用增加的开销抵消。MATH中Utility24相对自身Utility16输出缩短5.75%，但调用密度增加7.66%、每调用成本增加4.22%，自然时延仍增加5.75%，等128增加10.60%。不能把输出变短当成计算更高效。

SQuAD和JSON全部块长/近似组均零regret，最终轨迹与严格组相同。该设置没有触发近似收益；长块改变实际候选及验证轮，而不是提供了新的门控效果。短答案遵守EOS，代码和短问答不强制续写以造出128样本。

## 同前缀诊断提供的解释

这部分是**运行后探索**，单独存为`diagnostics/same-prefix.json`，不改变冻结主要比较。

- 在48题严格D的相同已确认token前缀上，24/16有773个匹配状态：长块在有效共同候选范围内更早拒绝190、更晚拒绝82、相同501；32/16为724状态：更早226、更晚76、相同422。
- 12个预定机制题能够直接查看候选ID：24/16的164个匹配状态中149个候选发生变化；32/16的158状态中145个发生变化。当前长块不是简单保留原16块候选再追加尾部。
- 36个“请求×长度”初始块中，四策略使用的proposal、Target top IDs和regret均一致；差别来自各自接受规则及后续路径，不是记录器偷偷换了候选。初始状态不能代表后续完整策略的同状态因果对照。

同一题的状态彼此相关，不能把这些计数当作独立样本做显著性声明；也没有逐位核对缓存隐藏特征。因此目前能确认运行中候选/接受前缀发生变化，尚不能唯一归因为训练块长外推、未来mask注意力或数值变化。结构/KV测试通过，只说明执行正确，不保证外推预测有效。

## 质量问题已复核

基础ASD32出现两个额外失败，严格D32在同题仍通过：

- MATH448求17在模83下的逆元，正确答案44；ASD32输出49，而17×49 mod83＝3，并非要求的1。这是实际错误，不是数学格式等价。
- MBPP504测试要求`sum_Of_Series`，ASD32定义了`sum_of_series`，测试因未定义请求的函数名失败。它是大小写敏感的接口合同问题，没有通过重命名输出或放宽评分消除。

MATH444所有13组最终均错：Utility16达到4096且没有boxed答案，其余正常结束但给出错误的k函数。参考结论对所有正k均为1/2；对本轮六种已观察表达式显式代入k=3，均可反驳。`quality-review.json`保存13项辅助复核及两个额外失败，主分数未改。Utility24相对ASD16在共同正确EOS的7道MATH上仍慢10.17%，主负结果不由旧截断单独造成。

代码没有因受限import等原因未评估的项。各策略总预算仍守恒；logit-regret预算不保证最终答案或接口正确。本轮没有单token因果干预，不把上述失败归因给某一个未经干预验证的例外位置。

## 后续研究

保留成熟D16、基础ASD16及此前独立收益证据。当前b16权重直接扩到24/32的实现停止继续扫长度或价格，也不消费验证集确认一个没有清晰优势的候选。

下一项按[研究路线表](ASD_RESEARCH_ROADMAP.md)检查GPU执行开销：先用短的独立profile和非插桩控制，量化可削减的同步、验证器和模型执行成本，再决定设备账本、融合或图捕获是否值得实现。当前每调用摊销成本不能回答这些细分问题，不能先许诺加速。专用长块训练、多候选、调度和并发仍保留为未完成方向，不把本轮负结果当成它们已经失败。
