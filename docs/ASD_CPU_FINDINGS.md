# CPU摘要判定：可保留的小幅执行收益

**精简判定有效，但端到端只获得约0.3%–0.7%的时延下降。** 本轮适合保留为研究执行选项，已经完成可行性检查；主要优化资源继续转向Target/Draft模型执行，不继续围绕验证器做复杂调度或预算系统。

## 改了什么

新增显式`CPUASDVerifier`，GPU归约top分数/ID及候选分数，把最多15个位置的4K个FP32数一次传到CPU；CPU完成原ASD/Run/Utility规则。完整词表logits不传出GPU。Target、Draft、posterior argmax、KV和停止路径、预算/接受规则均未改，原验证器和默认infra保持不变。

FP32 ID精确范围及共同二进制格点界限制了快速路径，使FP64 regret前缀和/charge的求和顺序不改变结果。极端分数跨度、不支持的精度/块长/词表及自定义utility hook回退原实现，非有限分数报错。没有新增接受或预算容差。边界测试和当前实测一致，不夸大为任意硬件/全部输入已经逐项验证。

## 同轮配对结果

六类各前两道已观察开发题，仍是原生16块、FP32/eager、greedy、空历史、遵守EOS前128。7组含原生DFlash及三策略各原版/CPU版，每组每题5次，共420次计时。相同策略的两实现相邻、随机先后；策略构造成本单列并加回主时延，GPU摘要复制、CPU检查和回退都计入，模型加载和14个warmup另计。

每题先合并五个相邻pair的log时延比，再按题汇总。以下区间为六类别内各2题重采样的5000次bootstrap，只描述这个固定开发子集；不能外推为生产分布或独立验证。

## 为什么微基准改善很大，在线改善很小

同轮、同真实输入状态的resident回放，先对每题采样状态中位数汇总，再取12题中位数：

|方法|原Tensor判定ms|CPU摘要判定ms|成本约下降|
|---|---:|---:|---:|
|ASD|0.771|0.157|80%|
|Run|0.872|0.165|81%|
|Utility|1.053|0.160|85%|

每状态5次warmup后各30次回放，初始化及前置同步在计时外，调用及末尾同步计入。CPU方案确实减少了大量小GPU算子和调度，且保留约束检查；但是原判定只占请求很小的一部分，主要模型计算和原验证轮数没有减少。因此当前0.3%–0.7%的净收益与上一轮约百分之一量级的估算相符，不能把微基准快约5–7倍直接宣传成生成快5–7倍。

上一轮profile之后的resident原版约1.08/1.22/1.49ms，本轮约0.77/0.87/1.05ms。跨轮绝对值不同的具体原因没有被单因素识别，可能的调度/运行历史差异不能写成已证实归因。本轮收益只使用同轮同状态、相邻交错的比较，不把跨轮变化算到CPU改动。

## 一致性、成本与未验证范围

420计时加36独立诊断共456次生成，输入SHA、snapshot、token/文本、每轮推进、接受/严格接受、regret、完整请求账本及停止原因均与原记录相同。36次原版生成中的430个实际块同时调用持久CPU影子，decision及summary逐项精确相等；完整候选和Target top IDs另由既有独立标量审计核对真实EOS。

77个实际0/4/12轮状态全部回放重现，短回答不补轮；430影子块、2150次正式CPU判定均走快速路径，回退次数0。实验没有隐去回退成本，数值边界回退已在单元检查覆盖。原生DFlash同轮对照60次保留且重现旧严格轨迹。

这里没有新的4096自然完整答案评测，也没有使用validation/reserve。128轨迹一致不等于所有自然长度已经实测相同，更不能由执行优化宣称近似ASD成为无损解码。当前证据也不改变Run/Utility尚无稳定独立算法优势的旧结论。

本地完整629 passed/5 skipped/70.22s，服务器相关98 passed/9.46s。冻结`c75328fa8e03da09a262754a2e9e9207d6bdc5e2`的1285部署文件运行前后相同；13个执行/协议/统计文件未改，844旧结果SHA与四批151个发布文件核验通过（两个已知CRLF例外单列）。默认运行时/评分等6文件与上一发布逐文件一致，三个infra引用仍为`27e3619`。
