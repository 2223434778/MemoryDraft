# ASD七任务扩样本：保留成本受控树组合，Joint作为消融

2026-10-24。**BudgetTree-ASD在新GSM8K样本上保留了明确的增量收益，是当前优先推进的方法；Joint没有显示进一步稳定收益。** MATH也有速度及答案正确数的改善。代码、短选项和开放对话各有不同边界，不能合成“所有任务无损加速”。

本轮已完成241个此前未使用的公开源任务、249个匹配输入请求、五方法4980次正式计时、249次AR参考。另有40次使用各自首轮回答的MT第二轮、18次预热/零预算检查，以及192条本地裁判记录。任务名覆盖ASD论文七类，但采用Qwen3-8B/DFlash、两张A6000、FP32/RMSNorm，不是论文DSpark/L20、原始完整数据与提示协议的精确复现。

完整冻结统计在[主表](ASD_PAPER_RESULTS.md)和[analysis.json](../results/asd-paper/analysis.json)，预先约定在[协议](ASD_PAPER_PROTOCOL.md)。下文质量复核只添加解释，不重写原评分、不删慢题或错题。

## GSM的正结果来自什么

组合较严格DFlash自然时延低18.98%，较严格BudgetTree低8.36%；等128较严格树低8.25%。因此正结果同时包含树搜索的贡献和ASD在树上的额外贡献，不是只打败较弱线性基线。

相对ASD，组合逐题输出长度比平均**增加1.91%**，而调用密度平均下降18.02%；共同正确且正常结束的63题仍省9.69%自然时延。这不是靠提前结束或剔除错误答案才出现的速度。所有组同一题的正确集合保持63/64，但近似方法的完整token序列会变，不能称为与AR无损一致。

五组共同达到128的63题均生成8064 token：

|方法|Target调用|验证节点|总wall秒|
|---|---:|---:|---:|
|DFlash|1495|22934|114.093|
|ASD|1343|20537|103.451|
|BudgetTree|1185|35256|99.171|
|BudgetTree-ASD|1069|31940|90.639|
|JointTree-ASD|1066|32145|90.367|

树使用更多节点，但减少调用足以抵消节点和在线构树成本。Joint只再少3轮，却多205节点；同一子集总wall略少，主指标的题等权比值略慢，均不足以支持独立附加收益。原开发8题上Joint的小收益仍保留，扩样本没有复现其增量。

固定256、忽略EOS的组合总吞吐为95.721 token/s，普通ASD为85.250，增加12.28%；Joint为95.660，与组合基本相同。这支持等生成量计算效率改善，但固定256有10.52%的组合token位于首次EOS之后，不能把该吞吐直接换算成真实请求收益。共同128同样不是完全相同中间状态的因果消融；本轮证据是冻结算法的在线比较，不虚构同前缀干预。

## MATH的收益和Joint失败

组合正确数26→28：新增答对180、421、425，失去485；全部32题正常EOS，ASD有3题到4096上限。自然长度比平均缩短6.36%，所以11.42%的完整时延收益含解答路径改变和避免循环。共同正常结束29题仍省4.82%；共同正确且正常结束25题省2.17%，区间跨1。这些是后验诊断，不替代全32题主表。遵守EOS的等128省4.70%，说明也有计算效率收益，不能把完整收益全解释为更强接受率。

Joint仅23/32，较组合失去180/355/358/421/425共5题，无新增答对；154和355到4096上限。复核9道涉及质量变化或未解析表达式的MATH题，没有发现可补记的等价正确答案：

- 358把椭圆答成圆：方程化为`(x−6)^2/40 + y^2/10 = 1`，两轴长度不同。
- 425的Joint表达式不是参考`3R²`的等价形式；取3-4-5直角三角形，Joint给475/24，参考为75/4。
- 421应满足`12x³+14x²−1=0`，原始整数系数和为27，Joint给22；ASD在重复讨论最小多项式中截断。
- 485的24种不闭合访问路径最短为13，组合与Joint给19，是真实错误。

全部个案、输出SHA、有限分数运算、代码反例和未完成轨迹解释在[quality-audit.json](../results/asd-paper/quality-audit.json)。不将原`needs_review`标签直接当已证实错误；这次逐项复核后才给出以上判断。

## 代码与短答案的失败边界

HumanEval组合快6.34%，但ASD的28/32变27/32：117丢掉`word.lower()`，把`Uncle`的U误算辅音；93漏掉换大小写后的大写元音替换。83从错误公式变成枚举并通过原测试，抵消一个损失，但没有证明枚举实现具有可接受的渐近复杂度。Joint没有保留这个新增通过，故26/32。代码质量损失不是答案提取格式差异。

MBPP主时延大幅退化集中于163：ASD为28 token/0.844秒，组合与Joint均输出至4096，分别23.722/31.099秒，反复展开嵌套表达式。主表不删该题；31个共同EOS题组合省13.31%，仅作为“减轮机制存在、尾部失败会吞掉收益”的解释。MBPP多数自然代码很短，128共同样本只有1或2题，不能据此推广长代码收益。

MBPP的两处通过差异需区别：506中组合计算组合数45，而测试要求排列系数90，是实际语义错误；214的`r*180/pi`与`r*(180/pi)`数学上相同，原测试的浮点精确相等却区分两者，60/120弧度只差一个ULP。保留原标准测试分数12/14/13，不把214宣传成推理质量下降，也不事后放宽原评分。32题中仅2题有challenge测试，五组均1/2，不声称完整EvalPlus。

MMLU主评分是提示要求的“只答一个字母”契约；**不能将32→25→22解释成知识正确率下降。** 全57题五组的可提取首选项逐题相同，统一提取首个`A/B/C/D`的补充诊断均38/57，均有3题没有这种开头。十处主评分差异均是同一个正确字母后多写了解释。多生成文字也增加自然时延；多数请求没有足够长的接续来摊销树成本。该补充不是偷偷改主评分，也不是论文完整MMLU accuracy复现。

固定256中，组合HumanEval/MBPP/MMLU分别有67.54%/77.06%/90.09%的token在首次EOS后；HumanEval固定TPS增加59.46%尤其不能当成正常短代码请求快59.46%。

## 开放任务：速度可记录，质量尚未确认

MT主性能的第二轮统一使用严格AR的首轮回答，保证Target输入相同。额外真实双轮使用每组自己的首轮回答，输入可以不同：8个对话总wall ASD188.950秒、组合161.667、Joint150.222，分别低14.44%/20.50%；这是一次完整自身历史轨迹的总量描述，不能混进主匹配输入表，不能据此宣布Joint在相同输入更快。

本地裁判192记录包括176实际前向、12相同文本自动平局、4超过4096输入上限未评。176次前向有170次选位置A、6次C；88对不同文本且双向可评的比较，**0对换序一致**。它未通过位置偏差控制，约50%的换序平均偏好几乎由位置倾向产生，既不能证明质量相当，也不能证明质量提高。保留全部失败记录，不通过重写提示或换裁判在本批挑选满意分数。开放质量需要以后独立可靠裁判或任务级人工核验；本轮只接纳速度信号，不接纳“开放质量已保持”的主张。

Alpaca组合自然时延区间[0.7538,1.0045]跨1，Joint[0.7771,0.9460]；这是16个指令的有限结果，且直接组合比较没有Joint优势。开放场景可作为第二适用方向，当前优先级低于已有客观答案的GSM。

## 接下来的研究选择

保留**成本受控树+ASD**作为数学场景算法主线，承认它在GSM的新64题上已经获得收益；MATH作为第二场景，报告路径和质量取舍。Joint的预算条件构树保留为有价值的消融，但不再围绕这批题调主干参数来追旧8题的小增量。

若继续推进，优先在另一个匹配Target/Draft或原ASD底座上检验第一组合的迁移，先冻结输入和配置，并给开放任务补可靠质量评估。另一个有明确失败依据的问题是“近似续写如何保护停止和输出契约”：MBPP163循环、MMLU多写解释都指向这一点，未来可以做严格EOS/结构边界保护与同状态消融；当前只是待验证假设，不宣称已经修复。保留RMSNorm/缓存等共同工程收益，避免把它们重新包装为ASD独有算法贡献。
