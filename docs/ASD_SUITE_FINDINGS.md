# 跨任务第一阶段：差异来自哪里

本轮把研究从旧的4/8道开发题扩展到48道新开发题，覆盖六类任务。先建立基线，再逐项评估新方法；不是所有思路已经尝试完毕。数据总池192题，其中48验证、96保留题尚未生成模型答案。

## 实际结果

五组均为原Qwen3-8B/DFlash、FP32/eager、greedy、batch1、固定Target输入。每题自然EOS上限4096重复3次、遵守EOS前128重复2次，共1200次计时；另48次机制回放，不计入时延。两物理A6000按题分片，同题所有方法始终同卡交错运行。

## 机制与质量

1. **数学有基础ASD的计算机会。** GSM8K共同达到128的7题，ASD相对D时延低11.45%；MATH共同达到128的8题低18.80%。对应Run相对ASD反而慢6.37%/11.69%，Utility慢2.40%/4.72%。这支持继续研究数学场景，但不证明新增Run/Utility有独立吞吐收益；自然请求长度也会变化。
2. **问答和结构化提取不是同一种机会。** SQuAD输出仅2–8 token，所有方法输出相同；JSON的8题也均为零regret、相同生成轨迹。当前近似规则没有触发，时延差主要是检查开销和测量变化，不能解释成门控效果。SQuAD没有等128样本；JSON共同达到128的6题上ASD比D慢0.31%。这些结果只约束当前任务和规则，不否定长上下文、长JSON等其他设置。
3. **代码质量与时间会反向变化。** HumanEval:134中严格D/Run的结尾布尔条件不能通过测试，ASD/Utility生成了不同实现并通过；不能说近似接受必然损害质量。但HumanEval:60各组均通过，D只用39 token，ASD/Run/Utility用112 token、在docstring中重复了示例。因此更高接受量或更少调用密度，不保证完整请求更快。没有等128代码样本，不发布强制续写后的代码吞吐结论。
4. **截断必须保留。** MATH:444的AR/D/ASD/Run都正常结束但答错，Utility达到4096上限且无最终boxed答案。金标准是与长宽比k无关的1/2；前三种不同变量表达式代入k=2即可反驳，人工辅助复核确认不是格式等价问题。`quality-review.json`保留依据，主评分不改。Utility/ASD主自然时延比为1.0278；仅共同EOS且正确的7题为0.9654，是诊断子集，不能替换主结果或删去坏例。
5. **重复和统计边界。** 三次自然重复在所有题中token/轮次/账本一致；题级配对比使用5000次bootstrap，八题区间仍宽。`timing-repeat-detail.json`保留每组原秒数、中位数、inclusive IQR和极差。不以“没有显著差异”断言整个方向无效，也不凭一个区间宣称质量非劣。
