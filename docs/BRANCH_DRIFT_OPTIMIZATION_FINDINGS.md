# 按需JS、门控节点分配与独立分歧上限：结论

三项实现和七任务开发检查已完成。**按需JS保持现有决策；节点分配与分歧上限的组合进一步提高AR一致性，并在六类任务上比普通ASD更快。各任务仍有速度与质量取舍，旧方法继续保留。**

完整数字见[结果表](BRANCH_DRIFT_OPTIMIZATION_RESULTS.md)，固定规则见[协议](BRANCH_DRIFT_OPTIMIZATION_PROTOCOL.md)，[公开摘要](../results/branch-drift-optimization/)保存924计时、66冻结AR参考、源码清单、测试与恢复证据。此为62个既有源任务/66匹配输入的开发诊断，包含已观察错误；非新保留集、非全部MATH-500/完整HumanEval评价，单次计时不称重复稳定性。

## 已实现的方法

- LazyDrift-ASD：按最长路径/最低regret/最低索引排序可行端点，只检查可能获胜路径上的未知JS；失败边排除经过它的路径，缓存比较结果。最终提交与eager一致。
- GateTree-ASD：在Lazy上改用单节点扩展，rank0用q0，旁支用qr*(qr/q0)，复用成本表选择节点数。偏向高概率主干，近似边仍须通过真实Target兄弟覆盖、EOS保护、原ASD与JS门槛。是Draft启发式，未训练/校准门控预测器。
- TokenCap-ASD：仅在Lazy上加raw regret≤ln4，当前候选概率至少为Target首选25%，独立于剩余候选长度。
- GateCap-ASD：组合后两项。原ASD B8/.25/cap2、JS/ln2≤.1、树≤32、Target输入与停止规则保持。

## 按需JS确实保持决策，但端到端收益很小

66自然+66前缀共132对，token、停止原因、逐轮所选路径/接受长度/regret及总预算全部相同。自然回答总验证轮均3492、输出均27710 token。完整矩阵、输入快照与预算核对通过，本机独立重建与服务器analysis相同。

自然请求JS比较5848→737，减少87.40%；JS批2250→683。自然wall总和301.203→300.805秒，低0.13%；各任务直接配对均值约省0.01%–0.20%，单次计时不强调这些微小差异的稳定性。比较减少是明确的机制结果，不能称87%的整体加速。

gate摘要1.257→0.861秒，JS摘要0.707→0.211秒；JS包含在gate中，不能相加。说明本批该检查原本只占很小的wall比例。

## 收益来自哪里

相对Lazy，组合在GSM/MATH/HumanEval/MBPP/MMLU/MT/Alpaca的自然耗时分别−2.93%/−14.00%/−3.27%/+13.39%/−0.09%/−1.92%/+1.33%。节点分配没有在所有任务优于旧的成对树。

组合的自然请求平均节点28.59→16.75、平均最大树深8.29→8.60，总验证轮3492→3315；输出27710→25036。这是不同生成轨迹上的汇总，不能把所有差值都归因于单个算子或同状态树效率。

共同128相对Lazy：GSM−3.26%（8题）、MATH−2.88%（12题）、MMLU−1.11%（4题）、MT−1.19%（6题）、Alpaca+0.68%（7题）；两类代码本子集中共同达到128的有效题数为0。相对ASD，组合MATH共同128反而慢3.94%、MT慢1.17%，所以完整回答加速包含生成路径与长度变化，不能全部表述为每token吞吐提高。

独立分歧上限没有显示通用优势：MATH相对ASD慢1.96%、正确8→7；MBPP则快11.05%、正确保持5/8且AR一致2→7。因此保留独立选项，在MBPP本批有比组合更好的取舍，不作为所有任务统一默认。

严格成本树仍很强：66/66与AR一致。组合相对它仅MMLU快1.36%，其余任务慢约0.58%–4.61%。当前证据支持更好的ASD速度/保真取舍，尚不支持全面胜过严格树。

## 修复的旧失败与新增失败同时保留

- MATH372：旧Drift/Lazy4096 token、约33.5秒、截断且错误。TokenCap824 token/8.00秒、GateTree824/7.62秒、组合824/7.62秒，均正常结束并答对。GateTree/组合与冻结AR一致；TokenCap虽长度相同且正确，仍有token差异。
- HumanEval76：旧Drift/Lazy58 token、一次近似、原测试失败；GateTree/TokenCap/组合均59 token、零近似、恢复AR输出且测试通过。
- MATH101：旧Drift/Lazy3539 token正常结束且正确；GateTree与组合4096截断且错误。TokenCap3460正常结束但也错误。整体MATH正确数保持8/12，不意味着正确题集合或每题结果不变。不能把修复372说成已经解决长推导失败。
- MBPP：组合更接近AR，却丢失ASD原本答对的一题，5→4。严格AR参考本身也仅4/8正确；提高保真度没有自动提高任务正确率。

## 当前采用建议

保留Lazy作为不改变决策的精简实现；将GateCap保留为更高保真的候选，重点呈现本批MATH/HumanEval/MT的取舍。MBPP保留Lazy/TokenCap与旧树方案。GSM完整回答仍慢于ASD，不宣传全面加速；不依据数据集标签新增线上路由。
