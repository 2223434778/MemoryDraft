# Codex 的第一轮任务

> 当前阶段（2026-10-18）：用户已授权转为 infra 项目，先读 README 与 [INFRA_GUIDE](INFRA_GUIDE.md)。下文是原研究启动任务，保留用于核查，不应重复启动已完成的模型实验。

你负责实现 MemoryDraft，用户选择的开发执行模型为 GPT-6.1-sol。先读本仓库 AGENTS.md 和 ARCHITECTURE.md；实际模型与后端以环境核验为准。

## 第一部分：选可复用底座并跑通基线

1. 检查 GPU、显存、主机内存、依赖、已存在模型和可用网络，不覆盖无关项目。
2. 审查现有项目中独立 Draft 的输入、验证、KV 回滚和许可。重点查看 SAM-Decoding 与 RAPID 的相关部分；如已有更适合的成熟实现，可以选择并说明原因。
3. 优先为同一个独立小模型建立无历史 D、有历史 H 两种条件。不要把 EAGLE 当作可随意加 prompt 的独立 LM。
4. 锁定一个主底座、一个 Target、一个 tokenizer 兼容的小模型。确认匹配的成熟 Draft 基线是否有权重及运行路径，避免后期才发现不支持。
5. 跑通 8–16 个短请求的 AR/D，固定 Target 输入和 dtype，检查缓存是否真正使用，并记录端到端耗时。
6. 写 docs/BASE_SELECTION.md 和 docs/PROGRESS.md，记录上游 commit、许可、模型版本、实际命令与真实阻塞。

这部分是实施准备，不要求复现所有论文结果。没有蒸馏权重时可用普通小模型继续，但必须准确标注。

## 第二部分：立即实现核心 H

1. 用少量合法旧片段作为人工候选，只用于机制调试，不当最终检索性能。
2. H 使用固定记忆前缀、独立 KV 和已确认输出 token IDs；每次只起草短块，再由同一 Target 严格验证。
3. H/D 使用相同小模型、当前请求、通用起草规则，仅额外历史区不同；必要时增加 D+同指令消融。
4. 覆盖需要修改旧代码、原文复用、无关历史、过期冲突、空历史，以及全接受／拒绝／EOS／路由切换。
5. 把历史 prefill、追赶和切换全部计时；记录 H 的接受增量和净时间，不能只报接受率。

完成后进入第三部分的两层检索和 R/H/D 集成，再按架构第四至六部分推进。H 必须实现，但允许路由在无收益请求上不启用它。

## 第一轮回复格式

简短说明：选定底座及依据、具体修改、已执行命令与结果、未验证项、下一步。若硬件或权限阻塞，明确写出；不要把模拟测试当实际 GPU 性能，也不要仅生成一份新计划就停止。
