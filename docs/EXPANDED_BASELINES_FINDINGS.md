# 新增场景关键基线补全：结论

2026-10-31，复用原182个固定请求，AR、DFlash、严格成本树、官方BASTION、当前BufferedKV-ASD五组共910次自然生成全部完成。它们是相同输入、相同A6000/FP32/eager/RMSNorm窗口的直接对照。本轮没有修改接受条件、训练模型、重新选题或扫描参数；旧实验独立保留。

**当前方案在代码编辑、摘要和AIME25显示局部增量，相对BASTION的混合总耗时减少4.16%；IFEval则由BASTION领先。** 请求等权的整体配对平均只快0.17%，应将定位放在适用场景，而不是宣称所有请求普遍快4.16%。

当前通常以更小的树完成验证，减少每轮节点工作；在编辑和摘要上，即使轮数更多也可更快。BASTION本批实际预算几乎全部为32，IFEval有一轮64；其默认自适应范围32..8192没有人为收紧。这些轨迹支持“更低每轮成本换取端到端收益”的解释，本轮未做新消融，不能单独量化门控、分数复用和KV复用各自贡献。

IFEval的较小树带来更多验证轮，同时输出多8.87%，使当前整体慢于BASTION。AIME当前输出少2.95%，长度变化也是提速的一部分；不能把全部收益归为验证效率。代码编辑几乎相同输出量仍有5.02%的配对收益，是较清楚的适用场景。短答案长文任务主要受prefill影响，收益仅约1%。

节点、长度、同输出分解及整体配对值可复核于[comparison.json](../results/expanded-baselines/comparison.json)；它们是对冻结输出的事后描述，未增加GPU生成或调参。
