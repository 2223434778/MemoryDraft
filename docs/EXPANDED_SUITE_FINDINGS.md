# 新场景扩展：结论与适用场景

2026-10-31，182个固定新请求、三组546次自然生成全部完成。当前方案是 **DFlash + 高保真反馈成本树 + ASD + 最小增量接受 + 分数/KV复用**，结果行名为`BufferedKV-ASD`。本轮不调接受条件、不改模型/prompt，不新增参数搜索。

**本轮结论：当前方案的收益已覆盖指令遵循、代码编辑和摘要，并非只存在于数学。相对DFlash的速度/保真度组合有价值；相对普通ASD，代码编辑更准确，AIME和LiveCodeBench则仍有质量取舍。** 长文短答案的收益很小，不能把摘要上的收益外推到全部长上下文任务。

当前混合总耗时比DFlash少 **12.96%**，比ASD少 **12.16%**；相对DFlash总输出token只少0.056%。在当前与DFlash输出完全相同的146个请求内，当前配对平均耗时少 **10.77%**、合计耗时少14.89%。这说明观察到的提速包含实际执行收益，不只是提前结束答案；同输出子集是事后描述，不作为新的预选独立实验。

IFEval当前总token为28239，比DFlash的25939更多，但总耗时仍为716.635s对837.579s。MultiNews/GovReport的当前总token分别为3669/4036，DFlash为3668/4036；摘要收益同样没有依赖缩短总输出。Qasper/MultiFieldQA-en则平均首token就需要约3.97/3.66s，总输出很短，prefill占主要部分，解码树的可优化占比有限。

146/182输出与严格参考相同，高于ASD的31/182，是本轮的输出一致性证据。它不是分布无损证明，也不替代质量评分；本轮没有新跑AR，DFlash身份不能写成已验证AR身份。AIME当前只有7/30个输出与DFlash完全相同，说明高难长推理仍容易分支漂移。

## 需要保留的取舍

- IFEval总通过数相同，但题目集合有交换：当前失去DFlash通过的1127，新增3425；不能写成每题质量不下降。当前宽松请求53/64，ASD56/64，DFlash52/64。
- LiveCodeBench当前与DFlash的正确集合相同；相比ASD失去3个通过题、恢复2个，净少1。ASD有2次2048-token截断，当前/DFlash没有。
- CanItEdit当前与DFlash的正确集合相同，保留了ASD丢失的`79_int_to_key`、`97_nash_equilibrium`两题；当前逐题平均比ASD慢0.60%，而混合总耗时少1.56%，这两个统计不矛盾。
- AIME当前与DFlash的正确集合相同；ASD额外通过20、8两题。当前/DFlash/ASD截断分别10/11/11，输出上限4096、非thinking配置，不能把5/30解释成模型最大数学能力或完整长推理结论。当前总耗时比ASD少4.97%，但逐题平均慢4.60%，同样应分别报告。
- 摘要仍有上限效应：MultiNews当前与DFlash各4/8截断，GovReport三组各5/8截断。GovReport当前ROUGE-L比DFlash低0.25分、比ASD低0.87分；本轮没有追加人工事实性评分。

## 数据与评分修订

固定数据、上游commit/许可、样本选择与SHA见[manifest](../data/research/expanded-suite/manifest.json)和[协议](EXPANDED_SUITE_PROTOCOL.md)。LongBench共32题，其中19题采用相同的3840-token首尾截取；它是受长度限制的比较，不是完整LongBench排行榜或真实超长上下文能力证明。LiveCodeBench来自v6分片，按easy/medium/hard各8选题，使用全部公开/隐藏测试。

CanItEdit初版规范答案预检23/32；独立v2修复对象方法/科学依赖误拦后29/32。核验规范答案日志又发现`-I`子进程未加入已安装z3的目录，以及`-c`执行无法支持测试中的`inspect.getsource`。v3只改为可信依赖路径+临时源码文件执行，规范答案31/32通过，统一重评全部96个输出。仅`78_llm_inference`因依赖额外Flask/vLLM推理服务不可评分；没有加载额外模型。旧预检/评分、失败测试、原始生成行SHA均保留；未改测试或根据模型答案调评分。评分仍是受限Python3.11执行，不冒充官方Docker环境或通用安全沙箱。
