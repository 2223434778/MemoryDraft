# H 的两个追加归因实验

2026-10-17。用户授权执行。沿用六个已测合成项目，只作追加机制/工程诊断，不声称是新的独立保留集。复用 Transformers 4.52.2 的生成、验证和 KV 机制；不增加推理引擎或上游代码。

## 1. 过去回答来源是否影响候选质量

- Target/S 固定 Qwen3-8B/0.6B，FP32/eager、非思考 greedy，块长 2，当前回答上限 128，历史预算 512。当前请求 messages 和 Target prompt hash 与第二轮相同。
- 历史构造只读取 `data/research/history.jsonl` 中测试用户的原始 order=1 记录。由旧代码确定 lower() 的过去任务，由旧清单确定 ten minutes 的过去任务；不读取当前测试请求，不从当前答案逆向构造历史。
- 先保存过去请求（order=0），用同一固定 Target 的 AR 生成过去回答（order=1，上限 256），保存实际输入、token、生成成本、截断标记和 SHA-256，冻结派生历史。干扰记录及版本时间不变。未来版本不覆盖旧版本。
- 冻结后才读取当前请求（order=10）。人工预选相同合法记录，比较 D_native、D_format、H_empty、H_manual、H_teacher；另加 H_manual_matched/H_teacher_matched，以二者较短的原文 token 数截断双方作为长度敏感性检查。截断可能损失内容，不能当作完美的长度因果控制。
- 每个 AR 已确认前缀都评分，主指标为请求等权的 H_teacher−H_manual 连续接受长度，按请求 bootstrap；同时报告相对 D 的变化、首位命中、逐项目变化和 payload 长度。R 弱匹配分层始终使用原人工历史索引，不让历史来源改变分层标准。
- 新 AR 评分轨迹需与第二轮保存的 AR token、prompt hash 一致。该实验是离线候选质量诊断，不报告推理加速。

## 2. 相同路由规则的 H 开关

- 仍使用第二轮的人工历史，避免同时改变历史来源。所有方法冻结相同快照、Target 输入、R 完整历史索引及 D 原生上下文。
- `RHD_off` 和 `RHD_on` 调用相同 RHD 路由；唯一功能开关为 H 是否可用。保留相同的 R 冷却、D/AR 各两轮探测、EMA 和最小驻留规则；H 启用时增加其两轮探测，全部计费。
- 同批交错比较 AR、D_native、旧 RD（辅助解释旧基线）、RHD_off、RHD_on、RHD_on_cached。主 H 开关对比是 on/off；缓存版为已实现优化的补充对照，不把旧 RD 当成纯 H 开关。
- 六请求、三次重复、块长 2、输出上限 128。AR 也参与随机次序。缓存从空开始，查询始终在线编码，首次/后续访问分开报告。
- 报告全部在线成本、TTFT、接受量、验证轮次、路线占比、H 初始化/追赶及配对时间比。逐 token、Target prompt hash、snapshot 不一致则保存并停止。按请求重采样，重复不视作独立样本。

不根据本轮测试结果更换模板、块长、模型、样例或触发阈值。成熟 Draft B6/B7 不在这两个小实验中冒充完成。
