# 发布说明初筛小检验：结果解释与结束决定

2026-10-18。[运行前协议](RELEASE_TRIAGE_PROTOCOL.md)、[原门槛结果](RELEASE_TRIAGE_RESULTS.md)。18个请求已在A6000上完成；以下诊断不改变冻结数据、Target输入、原门槛、质量得分或停止决定，没有新增GPU生成。原始公开输出全部保留。

**决定：本次候选检查结束，不启动原拟最多48次加速方法计时。保留R+DFlash实现，当前证据不足以支持围绕这个五类JSON初筛任务继续投入长期记忆优化。**

原预定质量门槛没有通过：严格完整合同3/18正确、7/18合同合格、严格类别得分30/90、0截断。这里的“合同”包含每类只能给1–2条证据、所有证据都支持该判断；任一整体合同错误会将该请求五类全部计错。这些数字不能直接解释为模型只会分类3个请求，也不能把7项关键正类未通过评分全部说成模型漏掉了关键事实。

直接检查原始JSON后的诊断是：

| 项目 | 事后诊断结果 |
|---|---:|
| JSON可解析、版本和五类顺序正确 | 18/18 |
| 只看五类status正确 | 88/90（97.8%） |
| 五类status全部正确的请求 | 16/18 |
| 超出1–2条证据限制的请求 | 11/18 |
| 引用了不支持相应判断的行 | 9/18 |
| 关键正类的实际status漏判 | 0 |
| 关键类的status误报 | 1 |

证据超长与证据不支持相应类别两组重叠。例子包括把章节标题当具体漏洞证据、把纯类型修复或内部重构当功能行为证据，以及把已归为API迁移的条目再混入其他行为。两项真正的status分类错误为：Flask3.0.3把FIPS兼容处理当成已识别安全漏洞修复；Starlette0.47.0把类型注解调整/内部typing导入当API迁移。这些判断依据预先固定的应用定义和标签，不是对这两个项目的一般安全/兼容性结论。

标签由开发agent在推理前阅读来源完成，没有独立领域专家复核；分类和证据支持性诊断也受该应用定义与来源标注的限制。保留逐例原文、输出和允许证据行，供外部审阅。

工程上，证据条数可以由受约束JSON输出或应用层限制来处理，但简单截取前两项不保证剩余证据正确，例如标题行或纯类型行可能排在前面。证据支持性仍需要解决。移除条数上限、规范化或新提示应作为新公共基线另行评估，不能追认原试验通过。没有为此重跑模型或用gold选择“正确证据”。

**历史机会主要反映固定输出结构。**

原预定oracle对照将“当前prompt”与“prompt+合法过去回答”比较：12个有历史请求共2597个输出token，额外历史独有覆盖1633个，62.9%；六项目均超过原项目门槛。这个数字使用当前答案枚举最优接续，只是机会分析，不含在线检索、选源、KV追赶和模型成本。

检查输出后，新增一个探索性对照：从已有schema构造两个假想JSON示例，分别将全部类别置为`not_mentioned`或`review`，版本统一为`0.0.0`，唯一虚构引用为`L001`。两份示例共323个token，不读取版本说明、标签、任何当前答案或过去回答；它们是明确标注的合成候选资源，不伪装用户历史。每个来源边界独立，仍用同样的6-token锚点、最多32接续、至少8连续正确token的oracle覆盖口径。

加入这些静态示例后，历史在“prompt+静态schema示例”之外独有覆盖只剩96/2597，**3.7%**。原1633个历史独有覆盖位置中约94.1%被这个静态对照覆盖。说明本次输出中的大量可复用内容是JSON字段、固定类别顺序和常见status组合，不能把全部62.9%归为用户长期历史特有的信息。

这一对照是看过输出后增加的诊断：两个示例的格式选择有事后性，323-token资源没有与每个请求的1–2条过去回答严格配平，未计索引或运行成本。因此不能说它已经是更快的系统，也不能将3.7% token覆盖换算成3.7%的延迟上限。它足以指出必须比较静态结构候选这一混杂因素；原门槛和停止决定仍以预先固定的规则为准。

这个结果不证明所有自然语言结构化任务都没有历史价值。它说明本次五类短JSON初筛还没有给出足以支持新方法主线的应用证据。真实输入来源没有自动带来历史独特性；可重复输出也可能仅来自一个已知schema。继续换提示来修质量，仍不能自动解决研究贡献问题。

本轮完成后，不自动再轮换数据集、训练H或增加路由模型。现有工作可整理为可复现的R+DFlash工程实现、适用边界与负结果；若未来出现独立的真实应用需求及可验证的特定瓶颈，再据该需求重新立项。当前没有已经论证的下一项原创算法可以承诺。
