问题分为：旧加速是否有可复核的实际计算减少；候选优势来自JSON结构、请求中已有默认事实还是合法过去回答；确定性规则是否已足以生成这一合成任务的结果。

旧证据 `results/reuse-confirmation/` 只读。先用原audit核对4项目/8请求/96计时、token、快照、KV和summary；另核验tokenizer能复现原prompt哈希和输出。历史只保留同项目同record_id最新的artifact：首轮用初始过去回答，次轮用首轮完成的回答，禁止把初始和新版本一起当active历史。

新候选只接受当前benchmark的明确文本语法，不声称通用自然语言理解。候选函数仅接收request字符串，不接收项目元数据、评分标签、过去或当前答案：

- Structure：按schema、指定数组长度和缩进渲染；虚构project/example、item_00等标识，标量值改成按类型的中性值。
- Static：同上，保留请求明确给出的schema默认值，不使用真实project、对象名称或本轮override。每个schema两轮候选相同；它是请求中可见schema的固定模板，不称跨schema完全通用模板。
- Compiled：从同一请求解析字段/对象顺序、默认值和唯一timeout override，直接json.dumps(indent=2)。允许作为待Target验证候选，也独立检查这一特定任务是否可由程序完成。没有读取gold；输出一致性只在候选完成后评分。
- Context/Global/StaticGlobal分别为当前prompt、prompt+合法历史、prompt+Static+合法历史。

离线oracle枚举所有6-token锚点后的最多32-token接续，连续正确至少8才计位置覆盖，各来源与special token边界独立。此口径与先前初筛诊断一致，但不是现有在线matcher的完整模拟；它知道正确接续，属于乐观机会分析，不是在线接受率、延迟上界或速度。统计历史在各对照之外的额外位置；另检查原Global实际接受的R token，有多少位置也被替代资源的oracle覆盖，不将这个比例当因果时间分摊。

候选额外资源共同上限1536 token（不含所有条件共同的prompt）；超限即报错，禁止静默截断。保留各条件实际资源长度。组合条件比单源条件可用更多token，不能将其差异全部解释为来源相关性；本轮先回答自然资源条件下是否存在替代解释，未做逐token等长资源实验。

执行顺序：先CPU诊断并保存逐例候选/哈希/覆盖和原证据哈希；若需要区分实际在线速度，再在相同Target/DFlash上交错测同批条件。不得从离线覆盖直接宣布Static已达到旧19.4%的收益。若Compiled可精确还原全部输出、历史没有额外机会，则足以说明该合成任务不必依赖长期历史，允许不为此启动新GPU生成；此时明确静态资源的速度仍未测。

如启动在线计时，须先在本文件补齐冻结的方法、重复数、预算和计时边界，再部署运行；不依据速度挑选条件或更改Target。旧96次计时及来源SHA保持不变。不自动恢复H、扩展CI确认或换新任务。
